# Адаптивный балансировщик нагрузки с прогнозом всплесков: симулятор и эксперименты

Практическая часть НИР (МАИ, магистратура, тема: «Разработка адаптивного балансировщика нагрузки
на основе методов машинного обучения для прогнозирования всплесков трафика»).

**Важно: это симуляция, а не эксперименты в реальном Kubernetes-кластере.**
Симулятор написан на Python и воспроизводит упрощённую модель кластера. Перенос на реальный
кластер (kind/minikube, Istio/Envoy, Prometheus) является следующим этапом и здесь не сделан.

## Как запустить

```bash
pip install -r requirements.txt
python experiments/train_forecasters.py      # ~25 мин: AR, LSTM/GRU v1, ансамбли v2 (сиды 1000+); можно по частям: ... lstm2 / gru2
python experiments/calibrate_fallback.py     # порог fallback на валидационных сидах 2000+
python experiments/run_experiments.py        # ~1-2 мин: 7 профилей x 10 повторов x 17 конфигураций
python experiments/analyze.py                # таблицы, статистика, графики -> results/
python experiments/pareto.py                 # сравнение при равной стоимости (кривые потери - под-секунды)
python experiments/pareto_stats.py           # парные тесты при равной стоимости
python experiments/sensitivity.py            # чувствительность к T_start
python experiments/diagnose_forecast.py      # где прогнозист выигрывает/проигрывает (валидационные сиды)
```

Всё детерминировано сидами. Результаты: `results/tables.md` (таблицы), `results/summary.csv`,
`results/runs.csv` (все прогоны), `results/stats.csv` (Манн-Уитни + Холм против A3, A6, B6),
`results/pareto_*.csv` (равная стоимость), `results_v1/` (результаты первой версии, без S6 и v2),
`results/hypotheses.json` (проверка H1-H3), `results/figures/*.png`.

## Модель и допущения (параметры в `SimParams`)

- Шаг 1 с, длительность прогона 1800 с, запросы приходят Пуассоновским потоком по профилю λ(t);
  один и тот же поток используется для всех конфигураций (общие случайные числа).
- Под обслуживает μ = 50 запросов/с, очередь ограничена 100 запросов (потеря при переполнении).
  Запросы приходят равномерно в течение секунды; задержка считается по жидкостной модели очереди.
- Запуск пода T_start = 30 с, затем прогрев 20 с (холодный под даёт 30 % пропускной способности).
- HPA: период 15 с, цель 70 % CPU, допуск 10 %, окно стабилизации вниз 120 с (в Kubernetes 300 с,
  сжато вместе со временем), метрика запаздывает на 10 с, неготовые поды при росте считаются
  с нулевой загрузкой (как в Kubernetes).
- ПАБ: шаг управления 5 с, горизонт прогноза 60 с (12 шагов), N\* = max(N_min, ⌈max λ̂ / (μ·ρ)⌉),
  ρ = 0,7; веса w_i = max(ε, μ − λ_i)·min(1, возраст/T_ramp); fallback на LC + HPA по скользящей
  ошибке прогноза (порог откалиброван на валидационных сидах, не на тестовых).
- Обучение моделей на синтетических трассах (сиды 1000+), каждая трасса делится хронологически
  60/20/20 (обучение / валидация / отложенный тест). Тестовые прогоны: сиды 0-9.

## Ограничения (читать обязательно)

1. **Нагрузка синтетическая**, генераторы написаны автором. Трассы WorldCup'98 / Azure (профиль S6
   из плана) **не использованы**. Выводы справедливы для этих генераторов.
2. Модель обучена на том же семействе генераторов, на котором тестируется (кроме S5X). Это
   оптимистичная оценка по сравнению с реальной трассой.
3. Признаки прогноза: только rps и sin/cos времени. Задержка, CPU и очередь как входы **не
   использованы** (в описании метода они предусмотрены).
4. B3 использует авторегрессию (ridge), а не SARIMA/Prophet (в среде нет statsmodels).
5. Ступенчатые всплески S3 по построению **непредсказуемы** по истории ряда (нет предвестников),
   поэтому часть выигрыша ПАБ объясняется не прогнозом, а быстрой реакцией: оценка нагрузки по
   запросам в секунду каждые 5 с вместо реакции на загрузку CPU раз в 15 с с задержкой метрик
   (см. B6 в таблицах: «прогноз» без обучения даёт близкий результат).
6. p95 при переполнении очереди упирается в потолок (~2 с, длина очереди / μ), поэтому для
   сравнения на профилях со всплесками основными метриками взяты доля потерь и секунды
   нарушения SLO (доля плохих запросов > 5 %).
7. Результаты зависят от параметров модели (T_start, μ, amp всплесков). Для T_start проведена
   проверка чувствительности (`results/sensitivity_tstart.csv`), для остальных - нет.
8. Метрики `burst_detect` и `lead_s` (обнаружение всплеска и время упреждения) на S5/S5X
   неинформативны: всплески перекрываются, и тревога соседнего всплеска засчитывается как
   упреждающая (даже у naive получаются ненулевые значения). Для выводов не используются.
   Вероятность p у простых моделей задана правилом, а не обучена, поэтому F1 по всплескам
   сравним между ними лишь условно.
9. Статистика: 10 повторов на ячейку, поправка Холма применяется ко всему семейству сравнений с A3,
   поэтому она консервативна; не значимое различие не означает отсутствия эффекта.

## Важное методическое замечание: сравнивать нужно при равной стоимости

Качество любого метода можно «купить» запасом (ниже цель HPA, больше запас ρ у ПАБ), поэтому
сравнение точек с разной стоимостью некорректно (усиленные базы A5/A6 показали меньше потерь, чем
B8, но за большее число под-секунд). Основное сравнение: `experiments/pareto.py`,
`experiments/pareto_stats.py` и `results/figures/pareto.png`. При равной стоимости кривая HPA
практически совпадает с A3, а прогнозные семейства лежат заметно ниже.

## История изменений (честный журнал)

- v1: S1-S5, LSTM/GRU (1 слой, окно 24), порог fallback 0,5 (взят заранее, не срабатывал).
  Найдены и исправлены ошибки симулятора (одновременный приход запросов в секунде завышал задержку;
  HPA считал неготовые поды неверно и раздувался). Порог fallback откалиброван на валидации.
- v2 (после диагностики `diagnose_forecast.py`): добавлен профиль S6 (добавлен ПОСЛЕ того, как
  выяснилось, что у ступенчатых всплесков нет предвестников и прогнозу там нечего улавливать; результаты
  на S6 нужно читать с этой оговоркой), ансамблевые LSTM/GRU, усиленные базы A5/A6, калибровка fallback
  отдельно для каждой модели, сравнение при равной стоимости. Тестовые сиды 0-9 для подбора не
  использовались; v1 и v2 оба оставлены в результатах.
